# Product interview

Inspect the repository and relevant documents before asking questions. Do not ask for facts the project already contains.

Ask focused decision groups covering only what changes the result: user and problem, desired feeling, journeys, requirements, non-goals, states, data, privacy, auth, payments, accessibility, design direction, launch scope, success, and definition of done. Explain the consequence of a non-obvious choice and recommend a default when the user is unsure. Surface contradictions instead of silently choosing.

Write `docs/plans/<feature>/01-product-brief.md` using the bundled template. Label facts, decisions, and assumptions. Do not implement or write a master plan until the brief is explicitly approved.
