# UI/UX quality

Read the project `DESIGN.md` and platform conventions first. Inspect the real user journey, not only a static screen.

Check:

- clear primary action and information hierarchy
- platform-appropriate navigation and semantic controls
- consistent tokens and reusable components
- loading, empty, error, disabled, pressed, success, and recovery states
- touch/pointer/keyboard targets and focus behavior
- readable copy and progressive disclosure
- text scaling, contrast, screen-reader order/labels, non-color cues, RTL where relevant, and reduced effects
- stable state under rapid taps, cancellation, interruption, and navigation changes
- responsive/adaptive layout and realistic content lengths
- perceived and measured performance

Prefer restraint over decoration. A “cute” or expressive direction still needs clear hierarchy, usable controls, quiet repeated interactions, and intentional emotional moments.

Report issues by severity, user consequence, evidence, and concrete fix. Do not replace a project’s design identity with a generic reference style.
